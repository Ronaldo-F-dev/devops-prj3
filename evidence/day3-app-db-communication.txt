Resolution DNS interne (depuis le pod applicatif) :
$ getent hosts postgres
10.43.80.67     postgres.kps-tasks.svc.cluster.local

$ python3 -c "import socket; print(socket.gethostbyname('postgres'))"

-> Le nom court "postgres" (nom du Service) se resout automatiquement en
   "postgres.kps-tasks.svc.cluster.local", qui pointe vers le ClusterIP du
   Service PostgreSQL -- c'est CoreDNS qui fait cette resolution.

-> Confirme : le Service "postgres" est de type ClusterIP (par defaut, aucun
   type explicite dans le manifeste), donc uniquement routable depuis
